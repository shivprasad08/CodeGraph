# UX Profile

Generated by `setup-ui-ux-skills`. All UI/UX skills in this project read this file before changing layout, copy, or interaction.

## Aesthetic reference

- **Standard:** Apple Native
- **Notes:**
  - Generous spacing, unified corner radii (8px controls, 12px panels/cards), larger hit targets, smooth short transitions (150–220ms, opacity/transform only).
  - Neutral system palette, dark theme for v1 (built on tokens so a light theme can follow). Surfaces: canvas → raised → overlay, separated by 1px soft borders and one-step lightness shifts — never glow.
  - **Chrome is monochrome; colour is reserved for data.** Primary button is solid near-white on near-black; focus rings neutral. Colour appears only for graph node types (file / function / class / entry point) and health severity.
  - Typography: Geist (UI and prose) + Geist Mono (code, file paths, repo names only). Weights 400/500/600.
  - Density: landing page is generous; the graph app view may be denser than typical Apple Native (it is a code tool), but keeps the same radii, spacing scale, and calm surfaces.
  - The product is the hero: show the real graph and real screens instead of decoration.

## Banned anti-aesthetics

- Glassmorphism / `backdrop-filter` without a high-contrast 1px boundary (default: no blur at all)
- Floating pastel pill badges for ordinary metadata
- Arbitrary decorative gradients and neon glowing borders / `glow-*` shadows
- Multi-color radial or rainbow gradients on CTAs
- Cartoon empty-state illustrations (people waving / high-fiving)
- Nested scrollbars and icon bloat inside inputs
- **CodeGraph-specific:**
  - Particle / constellation / animated decorative backgrounds
  - Gradient text (e.g. one highlighted word in a headline)
  - Emoji used as UI icons (⚡ ✦ ⬡ ⚠ 🔴 🟡 ⚪ 🕸 etc.)
  - Vanity stat rows ("100% free", raw node counts as marketing)
  - Uppercase, letter-spaced "eyebrow" pills ("OPEN SOURCE · FREE · NO SIGNUP", "SEE IT IN ACTION")
  - Rotated / vertical text labels
  - Hover-only interactions with no touch or keyboard equivalent

## Accessibility target

- **Level:** WCAG 2.1 AA
- **Contrast:** ≥4.5:1 for normal text, ≥3:1 for large text, UI component borders, and focus indicators. Tertiary text must still meet 4.5:1 on its surface.
- **Touch / focus:** ≥44×44px touch targets on touch viewports; visible 2px neutral focus ring with offset on every interactive element; full keyboard access, focus trap + restore for overlays; respect `prefers-reduced-motion`.

## Brand tone and microcopy voice

- **Voice:** Utilitarian & Minimal
- **Capitalization:** Sentence case for UI copy and buttons
- **Notes:** Precise, plain, honest. Verb-first buttons ("Analyze repo", "Re-run analysis"). State real limits plainly (Python only, 60-file limit, AI summaries for the 60 most-connected functions, free-tier cold start). No hype words ("instantly", "in seconds", "revolutionary"), no exclamation marks, errors never blame the user and always offer a next step.

## Icon library

- **Library:** Lucide
- **Package / path:** `lucide-react` (already in `frontend/package.json`)
- **Notes:** 16px default, 1.5 stroke; 20px in primary toolbars. Replace all existing emoji icons with Lucide equivalents. No second icon set; no emoji as UI icons.

## Agent rules

1. Read this profile before creating or editing any UI, CSS, or microcopy.
2. Prefer skills by task: new page → `page-patterns` (name the pattern before markup); layout / chrome → `viewports`; forms → `forms`; overlays → `surfaces`; loaders → `loaders`; empty views → `empty-states`; motion → `motion`. Before finishing UI, run `ux-audit`.
3. Use only the recorded icon library (or project SVG path). Do not mix icon sets or use emoji as UI icons.
4. Never introduce items on the banned list.
5. Destructive actions always use an explicit confirmation dialog.
